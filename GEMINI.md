       - В исходном файле проектов колонка `Z2` не заполнена.

       - Формат: `XX.YY.ZZ` (первые 2 цифры — рубрика, соответствующая направлению конкурса).
       - Допускается указание двух кодов через запятую.
       - Неполные коды или знаки `???` из исходных данных студенты не додумывают (оставляем как есть / очищаем от `???`). Однако при вводе новых данных через интерфейс требуется строгая валидация формата.
    5. **Целочисленные финансы:**
       - Все плановые, фактические и поквартальные суммы строго **целые числа (INTEGER)**, копейки/дробная часть отсутствуют.
    6. **Автоматический пересчет таблицы конкурсов (`gr_konk`):**
       - В исходных данных конкурсов поля планового/фактического финансирования и количества проектов обнулены.
       - Должна быть реализована процедура, рассчитывающая агрегаты (`COUNT`, `SUM(план)`, `SUM(факт)`, `SUM(кварталы)`) по таблице НИР.
       - Процедура вызывается: 1) при начальной загрузке; 2) при любом изменении НИР (CRUD); 3) при выполнении процедуры финансирования.
    7. **Интерфейс без лишних сущностей:**
       - Никаких отдельных программ или кнопок для «восстановления данных» делать не нужно — целостность поддерживается на уровне СУБД SQLite и процедур валидации.

## 2. Вариант задания

- **Вариант №7: «Сопровождение конкурсов на соискание грантов»**
- **Объект разработки:** Автоматизированная система управления организацией и сопровождением проведения научно-исследовательских работ (НИР) по грантам.
- **Цель разработки:** Создание программных средств для накопления, хранения, проверки целостности и аналитической обработки данных о НИР, финансируемых в рамках конкурсов грантов, с реализацией функций выпуска распорядительных документов.

### 2.1. Исходный информационный базис и нормализация имен полей

По требованию Полотнова, все архаичные обозначения 90-х годов (`z1`, `z2`, `g1`, `k2`, `k12` и т.д.) заменяются на осмысленные, легко читаемые имена:

#### 1. Таблица вузов (`vuz`) — справочник:
* `codvuz` (INTEGER, Primary Key) — уникальный код вуза.
* `vuz_name` (TEXT, старое `z1`) — краткое наименование вуза.
* `vuz_full_name` (TEXT, старое `z1full`) — полное юридическое наименование.
* `vuz_short_name` (TEXT, старое `z2`) — аббревиатура (МЭИ, АлтГТУ и др.).
* `status` (TEXT) — статус организации (Университет, Академия, Институт).
* `city` (TEXT) — город.
* `region` (TEXT) — федеральный округ.
* `obl_code` (TEXT, старое `obl`) — код субъекта РФ.
* `obl_name` (TEXT, старое `oblname`) — наименование субъекта РФ.
* `department` (TEXT, старое `gr_ved`) — ведомственная принадлежность.
* `profile` (TEXT, старое `prof`) — профиль.

#### 2. Таблица конкурсов (`gr_konk`):
* `codkon` (INTEGER, Primary Key) — уникальный код конкурса (1..17).
* `konk_name` (TEXT, старое `k2`) — наименование конкурса.
* `plan_fin` (INTEGER, старое `k12`) — плановый объем финансирования конкурса.
* `fact_fin` (INTEGER, старое `k4`) — фактический объем финансирования конкурса.
* `fin_q1`, `fin_q2`, `fin_q3`, `fin_q4` (INTEGER, старые `k41`..`k44`) — поквартальное финансирование.
* `projects_count` (INTEGER, старое `npr`) — количество поддержанных НИР.

#### 3. Таблица проектов НИР (`gr_proj`):
* `codproj` (INTEGER) — локальный код НИР в рамках конкурса (старое `g1`).
* `codkon` (INTEGER, FK $\to$ `gr_konk.codkon`) — код конкурса.
* **Первичный ключ:** составной `(codkon, codproj)` (в коде SQLite также может использоваться суррогатный `id INTEGER PRIMARY KEY`, но логический уникальный ключ — строго `codkon + codproj`).
* `codvuz` (INTEGER, FK $\to$ `vuz.codvuz`) — код вуза-исполнителя.
* `vuz_short_name` (TEXT, старое `z2`) — краткое наименование вуза (заполняется из таблицы вузов по `codvuz`).
* `grnti_code` (TEXT, старое `g7`) — код тематики по рубрикатору ГРНТИ.
* `plan_fin` (INTEGER, старое `g5`) — плановый объем гранта (руб.).
* `fact_fin` (INTEGER, старое `g2`) — фактический объем гранта (руб.).
* `fin_q1`, `fin_q2`, `fin_q3`, `fin_q4` (INTEGER, старые `g21`..`g24`) — поквартальное финансирование.
* `proj_name` (TEXT, старое `g6`) — наименование темы проекта НИР.
* `leader_fio` (TEXT, старое `g8`) — Ф.И.О. руководителя НИР.
* `leader_post` (TEXT, старое `g9`) — должность руководителя.
* `leader_rank` (TEXT, старое `g10`) — ученое звание руководителя.
* `leader_degree` (TEXT, старое `g11`) — ученая степень руководителя.

## 3. Требования к интерфейсу (GUI на PyQt6)

Исходя из рекомендаций Полотнова М.М.:

1. **Главное меню:**
   * **«Данные»** — переключение таблиц для просмотра и редактирования:
     1. *«НИР по грантам»* (основная таблица);
     2. *«Конкурсы грантов»* (сводная таблица);
     3. *«Вузы»* (справочная таблица).
   * **«Анализ»** — аналитические сводки:
     * Распределение НИР по **вузам**;
     * Распределение НИР по **конкурсам грантов**;
     * Распределение НИР по **субъектам РФ / федеральным округам**.
   * **«Финансирование»** — специальная функция выпуска распоряжения о финансировании НИР и формирования ведомости по вузам.
   * **«Справка»** / **«Выход»**.

2. **Оптимизация представления таблицы НИР (критично для демонстрации Полотнову):**
   * **Порядок столбцов:** Длинное наименование темы НИР (`proj_name`, 200+ символов) **сдвигается вправо**. Ключевые поля (коды, вуз, руководитель, финансирование) размещаются компактно слева, чтобы помещаться на экране без горизонтального скролла.
   * **Заголовки столбцов:** Задаются компактными русскими названиями (*«Код НИР»*, *«Конкурс»*, *«Код вуза»*, *«Вуз»*, *«ГРНТИ»*, *«План (руб.)»*, *«Факт (руб.)»*, *«Руководитель»*, *«Тема НИР»*).
   * **Панель операций:** Кнопки *«Добавить»*, *«Изменить»*, *«Удалить»*, *«Фильтр»*.

## 6. Правила работы ИИ-агентов

1. **Стиль кода (скилл `humanize-code`):**
   - Никакого «нейросетевого мусора»: исключить избыточные обертки, бессмысленные комментарии, пустые блоки перехвата ошибок.
   - Код должен выглядеть как написанный аккуратным студентом-инженером: лаконичный, модульный, структурированный.
2. **Оформление отчетов (скиллы `humanize-practice-report` и `humanizer`):**
   - Строгий инженерный язык кафедры УИТ МЭИ, соблюдение ГОСТ.
   - Обязательное удаление штампов ИИ («не просто X, а Y», искусственных триад, пафосных заключений).
3. **Безопасность данных:**
   - Файлы в папке `Источники/` являются эталонными и только для чтения.
   - Папка `AI_agents/` — рабочее пространство для служебных скриптов и временных логов. Основной каталог `BD/` не засоряется мусорными файлами.
